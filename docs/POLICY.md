# auctelis policy file (`.auctelis.yml`)

Repository-level defaults for the **Action mode label** and optional
**maintainer research scan** (`auctelis-dev scan`). The product gate is
**lock-only** — `fail_on` never fails the required Action check.

| Item | Value |
| --- | --- |
| Contract | **1.3** (`require_review` / suppressions apply to maintainer scan) |
| Product default | `mode: advisory` (comment-only); `fail_on: never` (no promotion) |
| Local CLI | Product `check`/`lock`/`gate` do **not** honor `fail_on` or suppressions, but `lock` seals the policy hash and any policy change is diffed as review-worthy (tier-2 growth) |
| Discovery (when trusted) | Look for `.auctelis.yml` **inside the scan target tree only** |
| CI trust | Action `trusted-policy=true` fails edits to an existing `.auctelis.yml` unless **base-ref CODEOWNERS** covers it; the tree-truth diff still shows the policy-hash change for review |
| Override | Explicit CLI flags always win |
| Disable research policy | `auctelis-dev scan --no-policy` |

## Product example (recommended)

```yaml
version: 1

policy:
  mode: advisory         # advisory | enforce — Action label only; init defaults advisory
  fail_on: never         # never promoted; research scan stays advisory in CI
  output_dir: auctelis-out
  ignore: []
```

Generated by `auctelis init --owner security`. Committed template:
[`../tools/auctelis/templates/auctelis.yml`](../tools/auctelis/templates/auctelis.yml).

## Maintainer research example

For `auctelis-dev scan` only (not the required PR gate):

```yaml
version: 1

policy:
  mode: advisory         # product default; use enforce with init --enforce
  fail_on: never         # never | high | any — research exit code only
  output_dir: auctelis-out
  baseline: .auctelis/baseline.json

  require_review:
    - remote_mcp_endpoint
    - privileged_hook
    - credential_access
    - unattended_execution

  ignore:
    - rule: AUCTELIS-RULE-003
      path: examples/**
      justification: "Non-production fixture"
      owner: security-team
      expires: "2027-01-01"
```

See [`../examples/auctelis.policy.example.yml`](../examples/auctelis.policy.example.yml).

## Semantics

| Field | Behavior |
| --- | --- |
| `mode: enforce` | Product/Action mode label; does **not** rewrite `fail_on` |
| `mode: advisory` | Does not change exit policy by itself |
| `fail_on: never` | Product default; research scan exits 0 on findings |
| `fail_on: high` | Maintainer: exit 1 on CRITICAL/HIGH `SECURITY_FINDING` or `EXPOSURE` |
| `fail_on: any` | Maintainer: exit 1 on any `SECURITY_FINDING` or `EXPOSURE` |
| `ignore` | Suppress matching findings before research gating; each entry **requires** `justification`, `owner`, and `expires` |
| `require_review` | Maintainer auto-fail when a matching finding exists (see `review_classes.py`) |

Gate classes for research: `tools/auctelis/security/gating.py`. `CAPABILITY`
never blocks under `fail_on=high|any`.

## CLI

```bash
# Product path — lock / Action (fail_on ignored for required check)
auctelis init --owner security
auctelis check
auctelis status --check

# Maintainer annotation (optional research job)
auctelis-dev scan . --policy .auctelis.yml --fail-on high
auctelis-dev scan . --no-policy
```

## Gate integrity

A policy file that the PR author can edit is not a gate. In CI:

1. Set Action input `trusted-policy: true` (default).
2. Default shallow checkout works (`action.yml` fetches the base ref at `--depth=1` automatically; `fetch-depth: 0` is not required).
3. Prefer the **Action-bundled tools** (no consumer `pip install`). The literal
   values `path` / `pypi` use a preinstalled `auctelis` on `PATH`; any directory
   input must be a pinned release checkout — never PR `./tools`.
4. CODEOWNERS must cover `.auctelis.yml` for policy edits; the tree-truth diff
   shows the policy-hash change for review even when the edit is authorized.
